# Встраивание отчёта сверки в 1С:УНФ (1С:Фреш)

## Назначение

Отчёт сверяет данные по заказчику ГАУ ЦТО между:

- 1С:УНФ — заказы покупателей;
- 1С:УНФ — расходные накладные;
- 1С:Бухгалтерия — реализации / УПД.

Основной разрез:

- контракт;
- заявка;
- товарная позиция.

Показатели:

- Заказано;
- Отгружено;
- Принято;
- Остаток к отгрузке;
- Остаток к приёмке.

Расчёт ведётся как в количестве, так и в суммах товарных строк.

## Период

Отчёт настроен на 2025 год.

Период определяется по дате Заказа покупателя в УНФ.

Связанные с заявкой расходные накладные и УПД учитываются независимо от даты их оформления, в том числе если они были оформлены позднее 31.12.2025.

## Текущая реализация

Расчёт выполняется на GitHub Actions.

Источники 1С читаются по стандартному OData только на чтение.

Результат публикуется в GitHub Pages.

Веб-отчёт поддерживает:

- раскрытие контрактов;
- раскрытие заявок;
- детализацию по товарным позициям;
- режимы "Штуки" и "Рубли";
- поиск;
- экспорт в CSV/Excel.

## Встраивание в 1С:Фреш

В арендной базе 1С:Фреш пользователь не может самостоятельно установить расширение или внешний отчёт.

Для размещения отчёта непосредственно внутри интерфейса УНФ требуется установка решения провайдером 1С:Фреш.

## Рекомендуемая схема

GitHub остаётся расчётным контуром:

1. GitHub Action читает УНФ и Бухгалтерию по OData.
2. Формируется готовый набор данных сверки.
3. УНФ получает уже рассчитанный результат.
4. В УНФ создаётся регистр сведений и форма отчёта.
5. Пользователь открывает сверку непосредственно из УНФ.

Это исключает необходимость повторять сложную логику сопоставления двух баз внутри 1С.

## Предлагаемая структура регистра

Одна строка регистра соответствует:

Контракт × Заявка

Поля:

- Контракт — Строка;
- Заявка — Строка;
- ЗаказаноКол — Число;
- ОтгруженоКол — Число;
- ПринятоКол — Число;
- ОстатокКОтгрузкеКол — Число;
- ОстатокКПриемкеКол — Число;
- ЗаказаноСумма — Число;
- ОтгруженоСумма — Число;
- ПринятоСумма — Число;
- ОстатокКОтгрузкеСумма — Число;
- ОстатокКПриемкеСумма — Число;
- ДатаОбновления — Дата.

Для детального отчёта по товарам может быть создан второй регистр:

Контракт × Заявка × Номенклатура

с аналогичными количественными и денежными показателями.

## Обновление

Для интеграции подготовлен GitHub workflow:

`.github/workflows/snapshot.yml`

Он формирует JSON-снимок результата без записи в боевые данные 1С.

Снимок может использоваться провайдером как входной формат для загрузки в регистр УНФ.

## Безопасность

Текущий контур использует OData только для чтения.

Логины и пароли не хранятся в исходном коде.

Доступы находятся в GitHub Secrets.

Перед включением автоматической записи в УНФ необходимо отдельно создать пользователя с минимальными правами на конкретный регистр сведений.

## Что требуется от провайдера 1С:Фреш

1. Создать расширение для УНФ.
2. Создать регистр сведений для результата сверки.
3. Создать форму списка / отчёта.
4. Добавить команду открытия отчёта в интерфейс УНФ.
5. Реализовать загрузку JSON-снимка в регистр.
6. Предоставить отдельного пользователя с минимальными правами на запись только в этот регистр.
7. После установки выполнить тестовый импорт и сверку контрольного контракта.

## Текущий внешний вариант

До установки расширения провайдером рабочий отчёт доступен через GitHub Pages.

Он уже работает на боевых данных и может использоваться как эталон результата при приёмке встроенной версии.
