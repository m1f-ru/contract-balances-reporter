# Расширение УНФ «Сверка ГАУ ЦТО» — сборка `.cfe` (этап B)

Всё содержимое расширения (регистр + отчёт + запрос) ниже. Собрать `.cfe` из этого — 10–15 мин в
Конфигураторе (или 1C:EDT). Node уже готовит данные для регистра (`scripts/push-report.mjs`).

**Кому:** человеку с доступом к Конфигуратору/EDT и правом загружать расширения в УНФ на Fresh
(проверка: УНФ → «Все функции → Управление расширениями конфигурации» → есть кнопка «Добавить»).

---

## Шаг 1. Создать расширение

Конфигуратор → Конфигурация → Расширения конфигурации → **Добавить**:
- **Имя:** `СверкаГАУЦТО`
- **Префикс:** `сгц_` (чтобы объекты расширения не конфликтовали с типовой)
- **Назначение:** *Дополнение*
- Режим совместимости — как у основной конфигурации (не понижать).

> Если ставите префикс `сгц_`, имена объектов ниже станут `сгц_СверкаОстатков` и т.д. — тогда для Node
> задайте это имя в переменной окружения `REGISTER_ENTITY` (см. шаг 6). Ниже — без префикса для читаемости.

## Шаг 2. Регистр сведений `СверкаОстатков`

Добавить в расширение **Регистр сведений** `СверкаОстатков`:
- Режим записи: **Независимый**; Периодичность: **Непериодический**.

**Измерения** (ведущие, вместе — ключ записи):

| Имя | Тип | Длина |
|---|---|---|
| `Контракт` | Строка | 50, переменная |
| `Заявка` | Строка | 50, переменная |

**Ресурсы:**

| Имя | Тип |
|---|---|
| `ЗаказаноКол` | Число 15,3 |
| `ОтгруженоКол` | Число 15,3 |
| `ПринятоКол` | Число 15,3 |
| `ОстатокКОтгрузкеКол` | Число 15,3 |
| `ОстатокКПриемкеКол` | Число 15,3 |
| `ЗаказаноСумма` | Число 15,2 |
| `ОтгруженоСумма` | Число 15,2 |
| `ПринятоСумма` | Число 15,2 |

**Реквизиты:**

| Имя | Тип |
|---|---|
| `ДатаОбновления` | Дата (состав: Дата и время) |

> Имена — **точно** как здесь (Node пишет ровно эти поля; регистр — латиница `_` нельзя, кириллица без «ё»).

## Шаг 3. Отчёт `ОтчетОстаткиГАУЦТО` (на СКД)

Добавить **Отчёт** `ОтчетОстаткиГАУЦТО` → открыть **основную схему компоновки данных** → набор данных **Запрос**,
вставить текст:

```1c
ВЫБРАТЬ
    СверкаОстатков.Контракт            КАК Контракт,
    СверкаОстатков.Заявка              КАК Заявка,
    СверкаОстатков.ЗаказаноКол         КАК ЗаказаноКол,
    СверкаОстатков.ОтгруженоКол        КАК ОтгруженоКол,
    СверкаОстатков.ПринятоКол          КАК ПринятоКол,
    СверкаОстатков.ОстатокКОтгрузкеКол КАК ОстатокКОтгрузкеКол,
    СверкаОстатков.ОстатокКПриемкеКол  КАК ОстатокКПриемкеКол,
    СверкаОстатков.ЗаказаноСумма       КАК ЗаказаноСумма,
    СверкаОстатков.ОтгруженоСумма      КАК ОтгруженоСумма,
    СверкаОстатков.ПринятоСумма        КАК ПринятоСумма,
    СверкаОстатков.ДатаОбновления      КАК ДатаОбновления
ИЗ
    РегистрСведений.СверкаОстатков КАК СверкаОстатков
```

В конструкторе схемы:
- **Ресурсы:** отметить все числовые поля (`*Кол`, `*Сумма`) — функция **Сумма**. Это даст подытоги по контракту.
- **Настройки → Группировка:** `Контракт` → внутри `Заявка` → (детальные записи). Вынести поля-ресурсы в колонки.
- (Опц.) Условное оформление: `ОстатокКОтгрузкеКол < 0` или `ОстатокКПриемкеКол < 0` — выделить цветом.
- Заголовок отчёта: «Сверка остатков ГАУ ЦТО (Заказано / Отгружено / Принято)».
- Форму отчёта не создавать — хватит автогенерируемой.

## Шаг 4. Собрать `.cfe`

Конфигуратор → на расширении ПКМ → **Сохранить как файл поставки/расширения** → выбрать **`.cfe`**.
(В EDT — экспорт расширения в `.cfe`.)

## Шаг 5. Загрузить в УНФ

УНФ (режим предприятия) → **Все функции → Управление расширениями конфигурации → Добавить** → выбрать `.cfe`
→ перезапустить сеанс. Проверить, что отчёт появился (Отчёты → по разделам, или «Все функции → Отчёты»).

## Шаг 6. Опубликовать регистр в OData (чтобы Node мог писать)

УНФ → **Все функции → Стандартный интерфейс OData → Настройка стандартного интерфейса OData** (или
«Настроить») → найти **РегистрСведений.СверкаОстатков** → включить → записать.
Проверить в браузере (Basic-auth):
`.../odata/standard.odata/InformationRegister_СверкаОстатков?$format=json&$top=1` → должен вернуть 200 (пустой список).

> Если объект с префиксом — сущность будет `InformationRegister_сгц_СверкаОстатков`; задайте её в
> `REGISTER_ENTITY` для Node.

## Шаг 7. Заполнить и открыть

- Запустить `node scripts/push-report.mjs --apply` (после шага 6 включим боевую запись в writer).
- Открыть отчёт `ОтчетОстаткиГАУЦТО` в УНФ → сформировать. Появятся Заказано/Отгружено/Принято/сальдо
  по контрактам (подытоги) и заявкам.

## Проверка «на берегу»
- Node готовит ровно поля регистра — контроль на `ОК32515258102`: заявка «1» = Заказано 535 / Отгружено 504 /
  Принято 431 / к отгрузке 31 / к приёмке 73; сумма заявок по контракту = контракт-итог (подытог отчёта).
- Если запись в регистр расширения через OData не заработает (шаг 6) — запасной путь в дизайне
  (`docs/superpowers/specs/2026-07-07-vnutrenniy-otchet-rasshirenie.md`).
